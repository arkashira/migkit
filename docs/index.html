migkit

Verify, repair, and move databases across engines - without trusting the mover.

postgresmysql mongodbmssql sqliteredis kafka+ cross-engine

Overview

Managed movers (AWS DMS, Tencent/Alibaba DTS, GCP DMS) and CDC engines move rows well, then leave the target broken in ways a row count never reveals: sequences that collide on the first insert, columns silently truncated, timestamps shifted by a timezone, text mangled by an encoding downgrade, partitions rerouted, constraints left untrusted. They only compare rows - never structure - and cannot repair a single row or roll back.

The rule migkit is built on: never let the mover be the judge of its own work.

migkit does everything around the move: it prepares the target, tells you exactly when to cut over, watches the load, validates the result down to every row and every object, and repairs what the mover could not carry. One command - migkit check - introspects the connection and runs every check that applies. You choose nothing.

Install

git clone https://github.com/arkashira/migkit
cd migkit && ./bootstrap.sh && source .venv/bin/activate

bootstrap.sh creates the venv, installs libpq, pulls optional drivers (mysql, mongo, redis, kafka) and the tools migkit drives (pg_dump/mydumper/pgloader, atlas, reladiff). Anything that will not install is skipped - every feature has a built-in fallback. Run migkit doctor --install to fill gaps on another machine.

Configure a hop

A hop is a source->target pair in conf/hops.yaml (gitignored, chmod 600):

hops:
  my-hop:
    engine: postgres            # postgres | mysql | mssql | mongodb | sqlite | redis | kafka
    source: { host: src.example.com, port: 5432, user: app, password: "env:SRC_PW" }
    target: { host: 10.0.0.10,       port: 5432, user: app, password: "vault:kv/db#pw" }
    databases: [appdb, orders]  # empty = discover from source
    db_map: { appdb: app_prod } # optional src->dst rename
    workers: 4

Passwords resolve from env:, file:, or vault: references - never plaintext in the file.

Commands

Eleven commands cover the whole lifecycle. Every check is read-only and rerunnable; every repair is dry-run unless --apply/--go, saves an undo first, and converges to the same end state on re-run.

check

Synopsis

migkit check HOP [--db DB] [--table SCHEMA.TABLE] [--only LIST]
                 [--consistent] [--drill] [--workers N]

With no --only, check runs the full battery - schema, counts, sequences, row-data checksums, and every deep check that applies to the hop. It is smart by default; the flags below only narrow or deepen it.

OptionEffect
--consistentchecksum every table inside one repeatable-read transaction per side, with the source LSN captured as a convergence fence (real diff vs in-flight)
--only LISTnarrow to a fast subset, e.g. --only counts,data
--table Tone table; with --drill, column-level sample diff
--db DBone database instead of all

Example

migkit check my-hop --consistent
# exit 0 = every row, sequence, object and deep check matched
# exit 1 = a diff; the report names which table, row, and column

assess

migkit assess HOP

Source-side readiness and operational health before you start the mover: server-version match, writable/read-replica endpoint role, wal_level, no-PK tables, and the replication health that can take the source down mid-migration - slot bloat, abandoned slots, WAL/binlog retention, and long-running transactions.

watch

migkit watch HOP [--verify] [--delta] [--interval S] [--count N]

Default: live counts, rate, ETA, replication state - and a cutover verdict. It names the source tables still being written (a queue/worker that the maintenance page did not stop) and only prints SAFE TO CUT OVER once the source is stable and the target has caught up.

--verifyre-run the read-only checks each cycle (continuous validation); transient lag heals, real diffs persist
--deltawith --verify: re-verify only the rows touched since the last verified point (WAL slot / binlog / change stream). Idempotent; runs forever on billion-row DBs.

sync

migkit sync HOP [--db DB] [--kind sequences|rows|schema|all]
                [--apply] [--go] [--on-conflict source-wins|keep-target]
                [--mode verify|seed|stream|migrate] [--serve]

Default reconciles the last check's diffs (dry-run; --apply to execute, --go to checkpoint for rollback). Sequence repair sets GREATEST(source, max(pk)) - safe by construction - and refuses to bump when the target is ahead of the source (a writer landed there). --mode runs the whole flow end to end so migkit can stand in for a managed service on a trusted VM.

move

migkit move HOP [--via auto|pg_dump|mydumper|pgloader|mongodump|debezium|builtin]
                [--mode full|cdc] [--go]

--via auto (default) drives whichever proven mover is installed; the built-in chunked copy is the crash-resumable fallback. --via debezium generates and supervises Connect configs for platform-grade CDC. Whatever moves the data, migkit verifies it.

Silent-corruption checks

The reason migkit exists. Each of these is a failure class where the mover reports success while the data is quietly wrong - drawn from real DMS / DTS / GoldenGate post-mortems. check auto-discovers which apply to your hop and runs them; you do not pass a flag.

CheckWhat it catches
sequence / identity collisionnextval <= max(pk) -> the first insert after cutover duplicate-keys. Repair to GREATEST(src,max), is_called-aware.
type-narrowingtarget varchar shorter, numeric scale/precision smaller, integer narrower, unsigned->signed - silent truncation / overflow
charset corruptionutf8mb4 4-byte truncation, latin1->utf8 double-encode mojibake, U+FFFD replacement-char excess, charset downgrade
uniform timezone offsetevery row of a timestamp column shifted by the same constant = a tz-conversion bug, not row corruption
collation unique-collapsedistinct source rows collide under a case/accent-insensitive target collation (data loss); glibc/ICU version drift corrupting btree unique indexes
partition routingrows stranded in the default / MAXVALUE partition, missing bounds, changed partition key
generated columnsstored value != its expression, expression drift, generated-on-one-side-plain-on-other
RLS partial-dumprow-level-security tables read as a filtered subset by a non-owner; RLS enabled with zero policies (default-deny lockout)
NULL vs empty-stringOracle ''=NULL flips IS NULL semantics and unique behaviour
no-PK tablesCDC silently drops their UPDATE/DELETE; unverifiable by key
constraintsFK orphans behind NOT VALID, untrusted / unvalidated CHECKs, deferrable-flag drift
parity gapsextensions, table & sequence grants, materialized-view freshness, column drift
float driftFLOAT/DOUBLE compared with a relative tolerance - catches real precision loss without false-flagging a faithful copy
replication healthslot bloat / abandoned slot filling the source disk, long-running transaction blocking CDC (in assess)

Postgres and MySQL carry the full set; MongoDB and MSSQL have the base layer with the smart set landing engine by engine.

Cutover runbook

# 1. before the move: readiness + source health
migkit assess my-hop

# 2. the managed mover (DMS/DTS) does the bulk load + CDC, OR:
migkit move my-hop --go

# 3. watch until it names the source quiet and the target caught up
migkit watch my-hop --verify --delta        # -> SAFE TO CUT OVER

# 4. quiesce writes, then the final fenced verdict
migkit check my-hop --consistent            # every row, object, sequence
migkit sync  my-hop --kind sequences --apply  # align counters, safely

# 5. green -> flip. red -> the report names exactly what and where.

Safety model

  • check, assess, watch, report, history are read-only and run anytime.
  • sync, move, schema --convert write to the target - all dry-run by default, requiring --apply/--go, each saving an undo first.
  • The source is never written. Nothing of migkit's own is written into the target - it stays a faithful copy; the audit ledger is local-only.
  • A lock file prevents concurrent writes; every write is recorded.

Engines

Native: postgres, mysql, mssql, mongodb, sqlite, redis, kafka. Aliases: mariadb, percona, aurora, alloydb, documentdb, azure-sql, tdsql. Generic (reladiff): snowflake, bigquery, redshift, clickhouse, oracle, duckdb, trino. Cross-engine: MySQL->PostgreSQL verified end to end.
