Telemetry

What migkit keeps about how it behaved, what it never keeps, the default, and how to turn it off.

What is collected

how migkit behaved: the command, the engines, the ways chosen and why (as codes), timings and rates in buckets, workers allocated and used, progress and how far the estimate was off, error categories, retries and recoveries, how much was verified and to which guarantee, how a run ended and what the operator stepped in to do.

What is never collected

rows, values, samples, keys or digests of them, statements, schemas, the names of databases, tables, columns or accounts, addresses, paths, connection strings, credentials, logs, stack traces and error messages. Every field is a closed code, a bucket or a bounded number; anything else is refused where the event is made.

Why

to tell which ways work on which engines and shapes, how good the estimates are, and where runs fail or need a hand.

Where it goes

this machine first: events are kept under the state directory in sealed, append-only segments of a fixed size, each chained to the one before, the oldest dropped past the number or age the organisation's policy keeps (telemetry_keep, telemetry_days). Nothing leaves on its own: migkit telemetry push <bucket> sends the sealed segments, once each, to an S3-compatible bucket you run and name, signed in with that store's own credentials, never a key migkit carries; migkit telemetry receive <bucket> reads them back and checks every event again. With MIGKIT_EGRESS=none, or a policy saying telemetry_push: off, nothing is sent and the push says why.

Default

on: events are kept locally; a push happens only when you run it. migkit telemetry show prints exactly what is kept.

How to turn it off

migkit telemetry off, MIGKIT_TELEMETRY=off, MIGKIT_EGRESS=none, or an organisation policy file (MIGKIT_TELEMETRY_POLICY, /etc/migkit/policy.yaml by default) saying telemetry: off. Off stops keeping events and deletes those already kept, the sealed segments not yet pushed included.

Every field an event may have

An event is one of these kinds, each field a closed code, a bucket or a bounded number; a field not listed here, or a value outside its codes, is refused where the event is made.
