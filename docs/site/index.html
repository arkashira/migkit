migkit

Move, follow, prove and cut over databases between any two engines.

migkit's own decision engine finds the fastest, exact, consistent way for each source -> target pair. Universal database migration, replication, and mathematical verification across 64 database technologies.

How it works

Every migration passes through four predictable phases, from pre-flight safety checks to verified zero-downtime cutover:

PhaseCommandActionOperational guarantee
1. Assessmigkit assess shopPre-flight audit of schemas, data types, sequences, and replication privileges.Read-only on source. Flags incompatible constructs before moving data.
2. Move & Streammigkit sync shop --mode migrate --goSnapshot table copy followed immediately by CDC change stream replication.Point-in-time snapshot. O(1) resume from key-range cursor if interrupted.
3. Verifymigkit check shop --deepInjective per-row hash + Merkle diff drilldown + 20 semantic drift audits.Never writes to either database. Detects silent corruption that count(*) misses.
4. Cut overmigkit move shop --mode cdc --drop --goSource writes drained, final stream sync drained, target sequences raised.Atomic switchover within outage budget. Reverse stream armed for rollback.

Quickstart

Install, configure, and execute a verified cutover in five commands:

# 1. Install via git
uv tool install git+https://github.com/arkashira/migkit.git
migkit doctor --install

# 2. Configure source, target and goal (passwords stored in keychain)
MIGKIT_SOURCE=postgres://app@db1.example.com/shop \
MIGKIT_TARGET=postgres://app@db2.example.com/shop \
MIGKIT_GOAL=cutover MIGKIT_HOP=shop migkit init

# 3. Run: snapshot copy + continuous change stream (CDC)
migkit sync shop --mode migrate --go

# 4. Prove: full row hash + deep semantic drift audit
migkit check shop --deep

# 5. Cut over: zero write loss, reverse stream ready
migkit move shop --mode cdc --drop --go

Click any parameter (shop, db1.example.com, full+cdc) to customize inline before copying. Detailed walkthrough: the quickstart guide.

Verification modes

Select the verification depth matching your operational maintenance window:

Command / ModeWhen to runScope & guaranteesComplexity
migkit check shopPre-cutover sign-offSchema structure, exact row counts, auto-increment sequences, and row hash blocksO(all rows) resumable
migkit check shop --deepCatalog & semantic auditDetects 20+ silent drift classes: NULL vs empty string, float precision, collation, unvalidated FKs, trigger statusO(1 fused scan)
migkit watch shop --verify --deltaDuring CDC replicationVerifies primary keys modified in WAL/binlog since last checkpoint; gates SAFE TO CUT OVERO(changed keys)
migkit check shop --sampleFast sanity checkTimes a bounded random sample of keys across tables without scanning full data volumeO(budgeted seconds)
scan (engine)Internal query plannerPacks up to 512 SQL aggregates into 1 range scan per side to minimize DB loadAutomatic in check

Core guarantees

  • Read-only on source: Source database is never modified unless explicit cutover is triggered.
  • O(1) Resumability: Checkpoints saved at key range cursor level; recovery skips completed rows in O(1) without re-scanning.
  • Zero silent corruption: Catches truncated LOBs, float precision errors, collation fold duplicates, and timezone shifts that pass naive row counts.
  • Guaranteed reversibility: Reverse stream back to old source is armed and ready from the second of cutover.
